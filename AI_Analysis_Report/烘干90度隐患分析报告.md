# 烘干温度 90 ℃ 隐患分析报告

> 分析方式：J-Link SWD **只读**在线观测 + 源码静态交叉验证
> 目标板：STM32F103RC（Cortex-M3 r2p1，256 KB Flash / 48 KB SRAM）
> 固件：`C7Detect.out`（Debug，本次未改动）
> 观测时间：2026-11-14 09:29 ~ 09:31
> 约束遵守：**未修改任何源码、未写入任何目标内存、未复位、未 halt CPU**

---

## 一、结论摘要（先看这 3 条）

### T-01 🔴 烘干设定 90 ℃ 会跨过"不可恢复"门槛

烘干路的两个上限是**硬编码绝对值**，而"软限幅"是**相对设定值 +5 ℃**：

```
TaskTempModule.c:253   if (wTempFan > (wHeatFanTemp + 50) && bySetDerat == 0)  → 软限幅，只 Stop，可恢复
TaskTempModule.c:265   else if (wTempFan > 920)                                → 硬保护，调 CloseHeatFan()
```

两者交叉点在 **设定 870（87.0 ℃）**：

| 烘干设定 | 软限幅（设定+5℃） | 硬保护 | 谁先命中 | 后果 |
|---|---|---|---|---|
| 750（75 ℃，出厂值） | 800 | 920 | 软限幅 | Stop PWM，降温后**自动恢复** ✅ |
| 850（85 ℃） | 900 | 920 | 软限幅 | 自动恢复，余量仅 2 ℃ ⚠️ |
| **870（87 ℃）** | **920** | **920** | 同时 | Stop + `CloseHeatFan()`，**不恢复** ❌ |
| **900（90 ℃）** | **950** | **920** | **硬保护** | `CloseHeatFan()`，**不恢复** ❌ |

**设定 90 ℃ 时，软限幅（95 ℃）永远轮不到，92 ℃ 硬保护成为唯一防线。**

`CloseHeatFan()`（`TaskTempModule.c:416`）只做两件事：`bHeatFanSta = false` + `DevPwm->Stop(1)`。
**不写错误码、不通知上位机、不自动恢复。** `bHeatFanSta` 只能由 `OpenFunHeat()`（`TaskMove.c:821`，内部调 `OpenHeatFan()` @ `TaskMove.c:824`）或复位重新置位。
现场表现：温度冲到 92 ℃ 后停止上升并缓慢下降，上位机没有任何故障码。

### T-02 🔴 88 ℃ 以下全部是 100% 满功率，2 ℃ 内不可能收敛

PID 输出到占空比的映射链（实测 `Kp=20 / Ki=0 / Kd=0`，`TaskTempModule.c:167-173`）：

```
fout = 20 × (Temset − Temin)/10 + 10
wPwm = clamp(fout, 0, 100)
PWM  = min(wPwm × 2, 100)          ← ×2 后撞 pwm.c:130 的 bySpd>100→100
```

代入 90 ℃ 目标实测推算：

| 实际温度 | fout | wPwm | ×2 | 实际占空比 |
|---|---|---|---|---|
| 25 ℃ | 1310 | 100 | 200 | **100 %** |
| 75 ℃ | 310 | 100 | 200 | **100 %** |
| 85 ℃ | 110 | 100 | 200 | **100 %** |
| 87 ℃ | 70 | 70 | 140 | **100 %** |
| **88 ℃** | 50 | 50 | 100 | **100 %** |
| 88.5 ℃ | 40 | 40 | 80 | 80 % |
| 89 ℃ | 30 | 30 | 60 | 60 % |
| 89.5 ℃ | 20 | 20 | 40 | 40 % |
| 90 ℃ | 10 | 10 | 20 | 20 % |
| 90.5 ℃ | 0 | 0 | 0 | 0 % |

**有效调节区只有 88.0 ~ 90.0 ℃ 这 2 ℃。** 加热体热惯性远大于 2 ℃ 所需的时间常数，
100 % 功率冲进 88 ℃ 后必然过冲。过冲 >2 ℃ 就直接撞上 T-01 的 92 ℃ 硬保护。

**这是"必然发生"，不是"可能发生"。**

### T-03 🟠 主路 900 保护会"连坐"关掉烘干路，且运行期无恢复路径

```
TaskTempModule.c:187   else if (wTemp1 > 900)  →  CloseTemp();
TaskTempModule.c:397   CloseTemp():  bHeatSta = false;  bHeatFanSta = false;  Stop(0);  Stop(1);
```

- 主路阈值 **900（90.0 ℃）是绝对值，不区分模式、不受 `bySetDerat` 约束**
- 一旦主路 NTC 读到 90.1 ℃，**同时关掉主加热和烘干加热两路**
- `RecoverTemp()` 全工程只有一处调用：`TaskMove.c:536`，位于 `MoveTask()` 进入 `while(1)` **之前**
- 即：**运行期触发一次就没有任何代码路径能恢复加热**，必须重启
- 同样**不写错误码**

主路阈值塌缩同理：

| 固化设定 | 软限幅（+5℃） | 硬保护 | 谁先命中 |
|---|---|---|---|
| 680（68 ℃，出厂值） | 730 | 900 | 软限幅，可恢复 ✅ |
| 850（85 ℃） | 900 | 900 | 同时 ⚠️ |
| **900（90 ℃）** | **950** | **900** | **硬保护，关两路** ❌ |

**固化设定超过 85 ℃ 即进入不可恢复区。** 若固化设 90 ℃、烘干设 90 ℃，主路会先撞 900，把两路一起关掉。

## 三、隐患逐条

### T-04 🟠 PWM 运行 83.3 分钟后自动停止，且可能不再重启

`pwm.c:99`：

```c
if (pstChn->stRun.dwStpCnt >= pstChn->stRun.dwStep) {
    *pstChn->stConfig.pwdPort = (1 - byActiveLevel);
    pstChn->stRun.blRunning = false;      // 静默停止，不通知上层
}
```

- `dwStep` 由 `TaskTempModule.c:173` 传入的固定 `50000` 决定（**已实测确认**）
- 10 Hz 输出 → 5000 秒 → **83 分 20 秒后自动断流**
- 重新启动的唯一条件是 `wPwm_Old != wPwm`（`TaskTempModule.c:171`）
- 恒温稳态下若 PID 输出稳定，`wPwm` 不再变化 → **不会重新 Write → 加热永久停止**

对本项目的直接影响：**老练（长时间连续运行）场景必然跨过 83 分钟**。
当前 Derat 工况下 `wPwm` 每 1.5 s 抖动 2~4 个单位，恰好不断重置计时，**掩盖了这个问题**；
一旦进入 90 ℃ 恒温、`wPwm` 稳定在个位数，就会暴露。

### T-05 🟠 设定温度改了，PID 的 `Temset` 不跟随

`TaskMove.c:1037-1038`：

```c
case C7_D_SETFANTEMP:
    g_pstC7SysPare->wHeatFanTemp = g_stC7.stIn.wParm[1]*10;
    break;
```

**没有任何范围校验**（原 `SetFanTemp()` 里的 700~850 检查在 `TaskTempModule.c:446-450` 已被整段注释）。

而 `stPiPidFan.Temset` 只在三处赋值：
- `PidInit()`（上电）
- `RecoverTemp()`（`MoveTask` 启动时一次）
- `OpenHeatFan()`（`TaskMove.c:824`，需单独命令触发）

**只发 `C7_D_SETFANTEMP 90` 而不补发开放加热命令，PID 仍按旧的 750 调节**，
同时 `wHeatFanTemp + 50` 变成 950，**软限幅被悄悄抬高**。这会造成"设了 90 但温度上不去，且过温保护变松"的组合现象。

另：正式命令 `CMD_C7_SETFANTEMP = 0x27` 走的 `SetFanTemp()`（`TaskMove.c:1495` 调用 / `TaskTempModule.c:444` 定义）**函数体全被注释，是空实现**。

### T-06 🟠 37 ℃ 关断阈值导致 100% 满功率 bang-bang 通断（本次实测到）

`TaskTempModule.c:259-263`：

```c
else if ((wTempFan > 370) && (s_stTempDat.bySetDerat == 1)) {
    s_stTempDatFan.wPwm_Old = s_stTempDatFan.wPwm = 0;
    DevPwm->Stop(1);
}
```

阈值是 **370 = 37.0 ℃**，而 Derat 目标 `Temset = 400 = 40.0 ℃`。
实测烘干路温度在 **37.0 ~ 37.7 ℃** 之间穿越该阈值：

- 37.1 ℃ → 走 Stop 分支
- **36.9 ℃ → 走 `wPwm_Old != wPwm` 分支 → `Write(1, 100, 50000)` → 100 % 满功率**

**本次 20 秒监控在样本 29 抓到了实际证据**：`chn1` 由运行转为停止，`dwStpCnt = 6`
（跑了 6 个 100 ms 周期 = 600 ms 满功率）。日志：
`Build_Logs/temp_guard_20261114_092902.log`

后果：降温/待机模式下加热器仍在"偷偷"以 100 % 功率脉冲工作，降温慢、能耗高、温控失准。
一旦进入 90 ℃ 烘干后再调 `DeratTemp()`，这个 bang-bang 会在温度降到 37 ℃ 后长期存在。

### T-07 🟡 主路关断不重置 `wPwm`，风扇路重置 —— 两路不对称

`TaskTempModule.c:182-186`（主路）：

```c
else if ((wTemp1 > 370) && (bySetDerat == 1)) {
    DevPwm->Write(0, 0, 50000);     // bySpd=0 被 pwm.c:129 直接拒绝
    DevPwm->Stop(0);                // wPwm / wPwm_Old 未清零
}
```

`TaskTempModule.c:259-263`（风扇路）：

```c
s_stTempDatFan.wPwm_Old = s_stTempDatFan.wPwm = 0;   // 清零了
DevPwm->Stop(1);
```

主路不清零 → 每个 PID 周期（20 ms）只要 `fout` 变化，就会先 `Write(0, wPwm*2)` **重新启动定时器**，
再被同一轮循环末尾的 `Stop(0)` 关掉。实测 `chn0.bySpd` 长期停在 100、`dwStpCnt` 恒为 0，正是这个原因。

虽然最终端口电平是低，但**每秒 50 次启停 PWM 定时器**，且存在 Write 与 Stop 之间被 1 ms 中断插入的窗口，
长期运行不是干净的状态。

### T-08 🟡 `dev_sum` 无界累积，float 精度已明显损失

`piheat_pid.c:68`：

```c
pstPid->dev_sum += pstPid->dev;                 // 每 20 ms 累加一次
```

- `Ki = 0`（实测确认 `0x20006918 = 0`），所以当前**不影响输出**
- 但实测 `dev_sum` 已达 **−442 559**（主路）、**−187 827**（风扇路）
- float 在 4.4×10⁵ 量级的 ULP ≈ 0.03，**累加已经在丢精度**
- `piheat_pid.c:74` 的 `if (fout > 300) dev_sum = 300;` 是**限错了对象**：应在 `dev_sum` 本身做限幅，
  现在变成"输出一超限就把积分强行设成 300"，一旦将来启用 Ki，积分会瞬间饱和

### T-09 🟡 5 分钟温升判定在高温目标下会误报

`TaskTempModule.c:152`：

```c
if (((TempData2 - TempData1) < 100) && (TempData1 < (stPiPid.Temset - 120)) && bySetDerat == 0)
    → C7SetErr(ERR_C7_TEMP);
```

- 判定条件：5 分钟内升温 < 10 ℃ 且起始温度低于"设定 −12 ℃"
- 90 ℃ 目标、大热容腔体：前 5 分钟从 25 ℃ 只升到 33 ℃ 完全可能 → **误报加热故障**
- 且 `else if` 链（`152` / `156` / `161`）使得 `TimeCount == 0` 那一拍不检查 NTC 故障码（`wTemp1 == 3000`）

### T-10 🟡 加热任务存在永久阻塞路径

`adc.c` 的 `ReadOne()` 每次调用都执行 `RSTCAL + CAL`，等待标志位用**无超时的 `while(...)`**。
`XH711.c:58` 的 `while (DevIo->Read(1, 9));` 同样无超时。

若 ADC 校准标志异常卡死 → `TempModuleTask` 永久阻塞在该循环内：

- **PWM 由定时器中断驱动，会保持最后一次设定继续输出**
- 若最后一次是 100 %，则 100 % 持续到 `dwStep` 耗尽（83.3 分钟）
- 无任何看门狗兜底（工程未启用 IWDG，`dev_config.h` 无 `CONFIG_PW`）

**这是"温度卡死在 90 ℃ 附近但还在加热"的最坏路径。**

### T-11 🟡 NTC 处于"半失效"区间时会被判成低温，继续满功率加热

`tempfan.c` 只在两端做故障判定：

```c
#define OPEN_VALUE  10      // ADC ≤ 10 判断路
#define SHORT_VALUE 4000    // ADC ≥ 4000 判短路
if ((wAdcMid <= OPEN_VALUE) || (wAdcMid >= SHORT_VALUE)) temp = 3000;
```

若 NTC 接触电阻升高（未完全开路），ADC 落在中间段 → 按公式算出的温度可能是 **−20 ℃ 甚至更低**。
此时 `wTemp1 > 900` 不成立、`wTemp1 > wHeatTemp+50` 不成立，
PID 认为离目标极远 → **持续 100 % 加热**。

软件层**没有"温度低于环境温度下限"的合理性检查**，也**没有独立硬件过温保护**在代码中体现。

## 四、为什么"温度越高越危险"——阈值塌缩图

```
烘干路：
  设定 75℃ ├──软限幅 80℃───────────── 硬保护 92℃ ────  余量 12℃  安全
  设定 85℃ ├───────────软限幅 90℃─── 硬保护 92℃ ────  余量  2℃  紧张
  设定 87℃ ├────────────────────── 软限幅/硬保护 92℃  余量  0℃  同时触发
  设定 90℃ ├──────────────────────────── 软限幅 95℃
           └──────────────────── 硬保护 92℃ ←── 先命中，不可恢复

主路：
  设定 68℃ ├──软限幅 73℃─────────────────── 硬保护 90℃   余量 17℃  安全
  设定 85℃ ├──────────────────────软限幅/硬保护 90℃      余量  0℃  同时触发
  设定 90℃ ├───────────────────────────── 软限幅 95℃
           └────────────────── 硬保护 90℃ ←── 先命中，关两路
```

**根因**：软限幅用"相对偏移"（+5 ℃），硬保护用"绝对常量"（900 / 920）。
两条线随设定值升高必然相交，交点之后保护策略从"可恢复的软限幅"退化为"不可恢复的硬关断"。

## 六、不改代码的前提下的临时措施

1. **烘干设定不要超过 85 ℃**（软限幅 900 仍早于硬保护 920）
2. **固化设定不要超过 85 ℃**（软限幅 900 与硬保护 900 重合，超过即进入不可恢复区）
3. 改完温度设定后，**必须补发一次"开放风扇加热"命令**，否则 `stPiPidFan.Temset` 不同步（T-05）
4. 出现"温度停涨且无故障码"时，优先读 `bHeatSta` / `bHeatFanSta`（`0x20006AB9` / `0x20006ABA`）：
   若为 0，就是撞了 900/920 硬保护，**只能重启恢复**
5. 老练连续运行超过 **80 分钟**时，中途主动触发一次温度设定变化或重启，规避 83 分钟 PWM 自停（T-04）
